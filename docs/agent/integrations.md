# Integrations

Behaviour, failure modes, and recovery for external systems. Overview of what
exists is in the root [README](../../README.md) "Automation & integrations".

## ezyVet browser agents (`agent/`, GitHub Actions)

- No API — Playwright drives a real Chromium session.
- **AWS WAF JS challenge** on login passes only with a realistic browser fingerprint. A login failure after a UI/agent change: check fingerprint/context options before suspecting credentials.
- **Report Queue keeps stale runs.** Downloads are matched against a queue snapshot taken before printing — preserve that logic or you'll ingest an old report.
- Large reports (Animals ~45k, Contacts ~33k rows) upload in chunks via `agent/lib/ingest.mjs`.
- GitHub cron is UTC-only: each job fires at two UTC times and the worker no-ops the wrong one. A "skipped" run is not necessarily a failure.
- Runs are recorded in `greendogops.agent_run` / `agent_run_log`, viewable at `/admin/agents`. A green Actions run is not proof the data is complete — check row counts and the latest data date.
- Workflows: `.github/workflows/ezyvet-*.yml`. Inspect failures with `GH_TOKEN="$GITHUB_TOKEN" gh run list --workflow <file>` and `gh run view <id> --log-failed`.
- **Tags** (record-tags worker, `ezyvet_tag` catalog). ezyVet exposes tags only through the Records filter's tag search box (`POST /General/DropDownList`, items carry `data-record-id` / `data-record-title` / "Title(Group)"). `node agent/ezyvet/list-tags.mjs` lists every tag read-only — the Pet Tag box plus every tag group (Breed, Species, Master Problem, …) — and `agent/ezyvet/tag-catalog.json` is the 2026-10-15 snapshot: 5,471 tags in 20 groups (Master Problem 3,480, Breed 1,127, Presenting Problem 621, General 41). Typing a label resolves only when exactly one tag matches (`selectIfOne`); names collide across groups, e.g. **"AP" (General, #5140) = Advanced Procedure** vs "ap" (MyPetClient, #6364). Pin each tracked tag's `ezyvet_tag_id` so the worker clicks the right suggestion (0253). After fixing a tag that has been failing, re-run it with `MODE=backfill ONLY_TAGS=<key>` — the nightly run only looks back 7 days.

## Vercel Cron (`vercel.json`)

- Every route authenticates via `isAuthorizedCronRequest` (`CRON_SECRET`); long jobs set `maxDuration = 300`.
- Jobs that post to Slack or send email are **externally visible** — never trigger them manually to "test" without authorization.

## LLM chain (`src/lib/ai/llm.ts`)

- `callTextLLM()` walks `LLM_PROVIDER_ORDER` (default Gemini → Groq → OpenRouter → OpenAI → Anthropic), temperature 0. One provider failing should degrade, not break; if *all* fail, check keys/quotas before code.

## Google, Slack, Resend

- Google auth: service account or stored OAuth refresh token (`scripts/google_oauth_setup.mjs`, `scripts/gmail_oauth_setup.mjs`). An `invalid_grant` means the refresh token was revoked/expired — needs the user to re-run setup; not fixable by code.
- Google Docs → Resources: policies are now **native Ops documents** (0235). To bring in a newly shared Google Doc or uploaded .docx, add it to `SOURCES` in `scripts/import_google_docs_native.mjs` (with the PDF/link row it replaces as `twin`, or `meta`), dry-run (writes the converted JSON/text to `.data/gdoc-native/` and reports a word-coverage % per document — below 97% fails the run), then `--apply`. It converts headings, nested bullet/numbered lists, bold/italic/underline/strike, links (Google-Doc links to converted docs are rewritten to `/resources/doc/<id>`), tables, horizontal rules, footnotes and inline + floating images (fetched from the Docs API `contentUri`, valid ~30 min; stored as data URLs ≤ 3 MB). Idempotent (skips native rows unless `--refresh`); point it at staging by exporting `NEXT_PUBLIC_SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY`. On 2026-10-12, 22 sources converted with 99.9–100% of visible words kept; "GDD Master Protocols Sheet" (`1m_b6JW0…`) returns 404 to both connected Google accounts and stays a link. `publish_google_doc_pdfs.mjs` (PDF export) and `ingest_google_docs.mjs` (link rows + text) still work but are superseded; the latter now leaves native rows alone.
- Resend delivery events arrive at `/api/email/webhook`.
- Calendar sync (`/api/calendar/sync`, `src/lib/calendar`) reads every calendar in `GOOGLE_CALENDAR_ID`, `GOOGLE_COMPANY_CALENDAR_ID`, `GOOGLE_DENTAL_CALENDAR_ID`, `GOOGLE_SOCIALS_CALENDAR_ID` and `GOOGLE_INTERVIEW_CALENDAR_ID` (list in `src/lib/calendar/calendar-env.ts`) as the service account `calendar-sync@greendogops-calendar.iam.gserviceaccount.com`. Each calendar must be shared with that address ("See all event details"), otherwise Google returns **404 Not Found**, not 403. A failing calendar is recorded in `calendar_sync_state.last_error` and makes the cron return 500, but the other calendars still sync. `GOOGLE_COMPANY_CALENDAR_ID` (a `…@group.calendar.google.com` "Socials Calendar") was set in Vercel on 2026-10-09 but never shared, so it returned 404 until it was removed on 2026-10-14; the account's own calendar, `greendogsocial@gmail.com` (no trailing s), is synced via `GOOGLE_SOCIALS_CALENDAR_ID` instead. A calendar added only under "Other calendars" in someone's own Google Calendar is still 404: the share must be on the calendar's own Settings and sharing page. The service account's `calendarList` is always empty, so test access with `calendars.get` on the exact ID; an empty calendar returns 0 events and 0 free/busy blocks, which looks the same as a free/busy-only share.

## Slack user linking (`src/lib/slack/users.ts`, `link-sync.ts`)

- Workspace `GREEN DOG` (green-dog-group.slack.com). The token's app is **GreenDog Ops** (App ID `A0C0W1RH58B`, bot user `greendog_ops`, bot id `B0C127HJT3L`). Ignore TEST APP and EmployeeGM Greendog: EmployeeGM is the other app on the shared Supabase project.
- Scopes are managed under OAuth & Permissions → Bot Token Scopes, then Reinstall. Adding scopes on 2026-10-09 kept the same `xoxb-` token, so Vercel needed no change. Verify scopes with `auth.test` and its `x-oauth-scopes` header; the granted list is in `.env.example`. Admin → Slack flags a missing `users:read` / `users:read.email`.
- Without `users:read.email`, `users.list` succeeds but omits every email. The sync refuses to run in that state, so it never marks everyone `not_found`.
- One `users.list` sweep (200/page) per sync; 429s are retried up to 3 times, honouring `Retry-After`. The sync is read-only toward Slack; it never posts.
- Matching is by exact email against `person.email` and the person's login email. Staff use the same personal Gmail addresses in Slack as in HR. A read-only preview on 2026-10-09 matched 87 of the 111 active employees and contractors, with 24 `not_found` and none ambiguous. Slack had 113 active human members, all with visible emails, plus 346 deactivated accounts.
- A connected link is kept by Slack user id. A deactivated Slack account becomes `inactive` (the id is kept) and is never re-linked to another account automatically. `disconnected` (unlinked by an admin) is left alone until an admin retries.
- Recovery: a failed nightly run shows in Admin → Agents (`slack_user_sync`) with the Slack error. `missing_scope` / `invalid_auth` need the Slack app or token fixed, not code.

## Twilio texting (`src/lib/sms`)

- Off until `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` and `TWILIO_MESSAGING_SERVICE_SID` are all set; until then nothing touches the `sms_*` tables (migration 0228).
- Test mode: unless `SMS_LIVE=true`, only numbers in `SMS_TEST_NUMBERS` can be texted.
- Every send is logged in `sms_message` *before* Twilio is called, and is never retried automatically (a timeout may still have delivered it). Staff see the failure and resend by hand.
- Before any send: allowed status (not `former`), US mobile number, consent (application `sms_consent` answer or an `sms_consent` row from `/apply` or `/texts`), no `sms_opt_out` row, 8 AM–9 PM Pacific, 60 sends/hour per staff member.
- Twilio console → Messaging Service → Integration: incoming messages webhook `https://greendogops.com/api/sms/inbound` (HTTP POST). The signature is checked against `APP_BASE_URL` + path, so the URL in Twilio must match it exactly — a mismatch shows up as 403s in Twilio's error log.
- STOP/START are recorded in `sms_opt_out` and Twilio's Advanced Opt-Out sends the replies. Twilio error 21610 means the number opted out at Twilio's level.
- Replies email the staff member who last texted that number.

The Console A2P wizard created it and moved +1 213-269-5208 into it. Inbound webhook `https://greendogops.com/api/sms/inbound`, `use_inbound_webhook_on_number=false`. Brand: **Mobile Vet Services, LLC** (dba Green Dog Dental), Standard, `BN1a3eed2b62a8b0c8cf2713abaf9927d7`, approved. Campaign `CM9d8d9309f16c08747b56110dc49337ac` (Low Volume Mixed, `has_embedded_links=false`, TCR `CGZN4D0`) was **approved/VERIFIED 2026-10-12**, the same day it was resubmitted. ## Notifications, Slack DMs and Slack workflows (`src/lib/notify`, `src/lib/worklist`)

- `publishNotification()` writes `user_notification` and, with `slack: true`, a `notification_delivery` row: `pending` when the recipient has a connected Slack link, `skipped` ("No connected Slack account") otherwise. It never throws.
- `/api/notify/dispatch` (every 5 min, `notification_dispatch` in Admin ▸ Agents; a run is recorded only when something was processed). DMs are sent only when `SLACK_DM_LIVE=true` or the Slack id is in `SLACK_DM_TEST_USER_IDS`; otherwise the row is marked `skipped`, so turning DMs on never sends a backlog. Older than 24 h → `skipped`. The row is claimed `pending → sending` before Slack is called. Only Slack's own "not delivered" answers (`ratelimited`, `internal_error`, …) are retried, up to 3 attempts. Timeouts and network errors are `failed` and never resent. A row stuck in `sending` for 15 min is `failed` with "may have been delivered".
- DMs use `chat.postMessage` with `channel = <Slack user id>` (scope `chat:write`, already granted). No `username`/`icon_url` on DMs.
- **Slack → Ops:** `POST /api/tasks/inbound`, `Authorization: Bearer $OPS_INBOUND_TASK_SECRET`, JSON `{external_id, assignee_slack_user_id | assignee_email, title, details?, due_date?, priority?, link?, created_by_slack_user_id?}`. Blank strings count as absent, because Slack sends empty variables that way. Responses: 201 created, 200 `duplicate` (same `external_id`), 400 bad payload, 401 bad or unset secret, 422 the assignee has no active login (their Slack must be connected, or the email must match exactly one login). A `link` on slack.com makes it an "Open in Slack" item. Workflow Builder has no plain outbound HTTP step. Call the endpoint from a custom step / Slack app function, or a connector (Zapier/Make).
- **Ops → Slack:** set `SLACK_WORKFLOW_WEBHOOK_URL` to a Workflow Builder "Starts with a webhook" URL. Ops then POSTs `{event, task_id, title, details, due_date, priority, assignee_name, assignee_email, actor_name, source, external_ref, link}`, all strings. It makes one attempt with a 5 s timeout and logs failures to the Vercel logs. `task.created` is not sent for tasks that came from Slack.
- Recovery: a failed DM shows its Slack error on the user's dashboard (Slack panel), in Admin ▸ Notifications ▸ Delivery log, and in `notification_delivery.last_error`. Never re-queue a `failed` row by hand unless you know it wasn't delivered; the log's Retry button is that explicit decision.
- **Engine (0236):** `emitEvent()` records a `notification_event` (idempotent on `dedupe_key`), resolves recipients from the rule (`notification_rule` override or the registry default) against the current directory (active employees/contractors + login + connected Slack), writes inbox rows (logins only) and person-addressed `notification_delivery` rows, then sends the immediate ones inline. The 5-minute dispatcher also: processes events left `pending` > 1 min (inline processing died), releases events stuck in `processing` > 10 min (3 attempts, then `failed`), creates escalations and next-day marketing reminders (from 10am Pacific), and sends batched deliveries as one digest per person. Each DM is re-checked at send time: still employee/contractor, same Slack id, still has `required_module` access.
- **Slack buttons:** Slack app ▸ Interactivity ▸ Request URL `https://www.greendogops.com/api/slack/interactions`, verified with `SLACK_SIGNING_SECRET` (5-min replay window, fails closed). The route answers 200 at once and does the work in `after()`; the clicker gets an ephemeral reply via `response_url`. Every click is a `notification_action` row (unique `request_key` = Slack user + `action_ts` + action + delivery, so Slack's retries are no-ops). A DM's buttons only work for its recipient; Approve/Deny need an active login with Scheduling edit rights and only change a request still `requested`. Results: Admin ▸ Notifications ▸ "Actions taken in Slack".
- **Card updates:** a delivery's `message_key` (e.g. `pto:<id>`, `task:<id>`) lets `resolveCards()` rewrite every sent card about that record via `chat.update` (buttons removed, "✅ Approved by …" added) and skip unsent ones. Needs the original `slack_channel_id` + `slack_ts`, which the dispatcher stores.
- **Channel posts** are by channel id chosen in Admin ▸ Notifications (`conversations.list` needs `channels:read` / `groups:read`). Public channels are auto-joined; private ones need `/invite @Green Dog Ops`, otherwise the delivery fails with `not_in_channel`.

## ADP RUN payroll import (`src/lib/payroll/adp-run.ts`)
- **No API on our plan** — Ops produces a file; Payroll uploads it in RUN at **Home ▸ Time Sheet Import**. If that tile is missing, enable it at RUN ▸ Settings ▸ General Settings ▸ Features and Services ▸ Payroll Features ▸ "Time Sheet Import", or ask ADP to turn it on.
- **Layout (researched 2026-10-14, not yet verified against our RUN account):** CSV with header `Co Code,Batch ID,File #,Reg Hours,O/T Hours,Hours 3 Code,Hours 3 Amount`. One row per employee carries Reg/O-T; each other earning (double time, meal premium, PTO) is an extra row with the RUN earnings code + hours. Sources: Redcort "Exporting to ADP Run" guide (company code, earnings codes report, employee codes report, Time Sheet Import), Kloqk "ADP timesheet CSV column reference" (Co Code / Batch ID 6-digit / File # / Reg / OT / Hours 3 Code+Amount pairs). ADP's own template wasn't publicly reachable.
- **Must match RUN exactly or hours are silently dropped:** company code (Admin ▸ Settings ▸ Payroll), earnings codes (RUN ▸ Reports ▸ Miscellaneous ▸ Earnings Codes), and each employee's File # / Employee ID (HR profile ▸ ADP RUN Employee ID; RUN ▸ Reports ▸ Miscellaneous ▸ Employee Codes).
- **Batch ID** = pay date YYMMDD, identical on every re-download of a period, so RUN can flag a duplicate import.
- **First run:** import a 1–3 employee test file, compare RUN's preview with "Summary with names", fix codes, then import the full file. If RUN rejects the header, take its template (or the When I Work RUN export header) and adjust `ADP_RUN_HEADER` / `adpRunCsv` + `adp-run.test.ts`.

- **Evidence:** `2305d18` → `dpl_5puFaqRMpx6FGPeXzxdEAUp5E4Jp` READY in production while the GitHub status was still `pending`.
